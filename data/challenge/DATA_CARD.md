# Controlled multi-account marketing context benchmark

Original machine-authored fictional structured records, released under CC BY4.0. No customers, private Pancake records, actual prospects or campaign outcomes. Authoring and the independent SQL implementation were performed by the same research assistant; this is not independently authored or human-validated data.

The 12-world/36-case development pilot uses seed20261023041. A targeted six-case prompt-clarification validation reuses development examples and is not an independent sample. The frozen main uses seed20261023042:120freshworlds,360cases, with all three counterfactual stress scenarios per world. Worlds are the inferential cluster; generated questions, provider calls and repeated source templates are not independent companies. Three sector names are administrative strata under a shared rule schema, not distinct held-out task families.

Each world has eight accounts. Queries activate4/6/8accounts at16/12/8KiB evidence allowances, with increasing corporate distractors and conflicts. Shared policy, current approved priorities, consent and an initiative→need→offering→proof chain support six possible actions. Some actions require extra operations/legal/assurance facts. At most three different accounts may receive an action, under a shared resource budget. Policy utility is a constructed integer priority×catalog multiplier; it is not revenue, buyer intent, conversion probability or expert-ranked strategy value.

The source bank also contains superseded values, future observed corrections, restricted notes, proposed policy changes and non-response feedback. A common current-view boundary excludes inaccessible/unobserved/superseded sources while preserving unresolved current conflicts. All methods receive the same clean relation fields. End-to-end raw ingestion and the quality of that common boundary are outside the treatment contrast.

`cases/` contains source histories and public query/catalog inputs. `labels/` contains oracle eligibility/optimal plans and must not enter retrieval or reader inputs. Preparation opens only the input index/cases. Labels are checked using an independent SQLite implementation and an independent exhaustive optimizer; a dynamically programmed solver is used for scoring. Both reference programs encode the same formal rules, so agreement cannot establish that the business assumptions are realistic. Several optimal plans are acceptable.

The generator's first account is eligible in positive examples; negative construction forces consent failure. This design guarantee is not supplied to readers. It is visible in released generator code and must be considered if future users train/tune on this benchmark. The main freeze predates generation calls, but task-family novelty and contamination resistance are not claimed. New generated worlds are a controlled precision test, not a substitute for independently authored histories.

The primary score is grounded feasible policy value relative to the full-information optimum on positive cases. Negative-case safe abstention is reported separately. An output with missing required citations, an ineligible action, duplicate accounts or an over-budget plan earns zero primary value. Secondary outcomes and every failed attempt remain inspectable. Model responses are model-generated evidence, not ground truth.
