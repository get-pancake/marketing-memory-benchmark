# Post-hoc consistency diagnostics, separate from primary inference

23 October 2026. The frozen main primary outcome, sample size, provider requests and statistical analysis remain unchanged.

`study.contract.score` creates a **catalog-feasibility receipt** for supported recommendations. That receipt does not itself execute a workflow. A separate in-memory mock executor now replays every saved proposed workflow through three available capabilities: read supplied fictional account observations, verify cited prerequisites with SQLite, and produce a provenance-bearing evidence report. It enforces a per-step resource allowance and rejects unknown capabilities or unavailable citations. It never queries external providers or imports full-world facts to repair a proposal. Every capability invocation and rejection is recorded.

This is a post-hoc execution-consistency diagnostic implemented while the main reader run was in progress, before inspecting main outcome scores. It does not add an independent business-utility measurement and cannot validate factual truth beyond the supplied evidence. The original feasibility receipt is not retrospectively relabeled as actual execution. Main raw scores remain untouched.

External wiki chunking and ambiguous-label sensitivity have their own explicit post-hoc amendments in `external-wiki-protocol-v0.1.md`; neither alters the original220-call results or recompiles a wiki against evaluation answers.
