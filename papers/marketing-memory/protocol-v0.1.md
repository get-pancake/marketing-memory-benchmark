# Paper A — domain-specialized company memory for marketing

Status: prospective design; **not a completed market benchmark**. Dated 22 October 2026. Amendments must precede dependent evaluation, preserve previous versions and explain any exposure to outcomes.

## Estimand and scope

Does a marketing-specific representation and evidence-selection policy improve the availability of current, permission-visible, sufficient context over strong general company memory at comparable resources? The domain is B2B marketing decision support. The tested representation, not the label "Brain", is the intervention. General memory may contain domain structure too.

The primary outcome belongs to the returned context, not a language model's eventual recommendation. A fixed reader is an optional downstream diagnostic. A stronger reader cannot retroactively change a retrieval score. No commercial utility, optimal action, graph superiority or whole-company replacement claim follows from context recall.

## Required comparisons

| Arm | Configuration and interpretation |
| --- | --- |
| Full permitted context | All source records when they fit; report actual cost, not a false matched-budget claim |
| Strong generic retrieval | Lexical+dense retrieval, provenance, time/access metadata and domain instructions |
| Generic plus domain instructions | Same representations/index; tests prompt/query specialization |
| GBrain native | Actual pinned upstream code with documented competent search configuration; verify embedding/vector path and do not call a keyword-only fallback hybrid |
| GBrain plus the same domain metadata/checklist | Separates missing task information from memory design; record configuration changes and tuning |
| Specialized memory | Same facts, backbone and resource accounting, task-aware evidence composition/update handling |
| Direct agent | Same raw documents, search/read tools and budget, with no maintained domain memory; model calls charged |

First run an inexpensive **component diagnostic** using actual GBrain hybrid search on the existing verified-event fixtures and common real embeddings. This uses a shared current-view filter and does not test GBrain's native temporal/permission ingestion, graph extraction, synthesis or hosted deployment. No result may be marketed as an end-to-end product ranking. Do not run only a deliberately weak keyword configuration and call it the market comparator.

The explanatory track holds the backend and representation information fixed where possible. A separate product-system track accepts implementation differences but cannot attribute its effect uniquely to specialization. Include a suitable independently authored public company-memory corpus after inspecting rights, task construction and scorer. Upstream AI-authored fixtures are external to this project, not independent human validation.

## Inputs and labels

Publish source documents/events, valid and observation times, approved/proposed/observed status, scopes and immutable source IDs. Keep labels, acceptable evidence sets, future information and outcome hints outside adapters. Split by company and task family, not adjacent questions. Existing v1 cases and outcomes are development/exploratory evidence for this amendment, never a newly sealed test set.

Include policy changes, corrections, weak feedback, conflicting sources, missing evidence and out-of-domain company questions. Broaden beyond contract-shaped template matching. Share raw documents in the end-to-end track and account for extraction/maintenance. Independently authored cases or blinded expert checking are a separate required validity milestone; software cross-checks do not satisfy it.

## Outcomes and analysis

Primary candidate: proportion of answerable questions with a complete acceptable current evidence set in the returned context at the fixed reading allowance. Freeze its exact definition before main execution.

Supporting outcomes: evidence-group coverage, stale/conflicting fact retention, negative-case apparent eligibility created by hiding a conflict, unauthorized/future evidence exposure, precision, retrieval/update latency, input volume, ingestion and update compute, and human maintenance effort where actually recorded. Coverage/absence must accompany precision so returning nothing cannot win. A context that lacks a needed record is not evidence that the record does not exist.

Use paired world-level estimates and intervals, retaining failures. Report out-of-domain spillover and per-condition outcomes. A component study with shared correct input filtering cannot claim learned authorization or native update quality. A post-hoc reanalysis must be labeled as such.

Pilot on development data, examine baseline competence and metric failure modes, then select the main size from company-level variance and practical precision. No desired positive result, inherited run count or number of repeated seeds determines sample size. Fix prompts, adapter versions, hyperparameters, configurations, splits, budget and analysis before main results.

## Publication gate

A compiled preliminary report is possible now. A defensible paper comparing vertical memory with market systems additionally needs actual competent comparator traces, an independent dataset/validation track, final protocol freeze, full cost/uncertainty analysis and a tested clean release. Missing named arms remain explicit; they cannot be filled by simulated scores.
