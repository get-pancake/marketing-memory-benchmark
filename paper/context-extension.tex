\section{Context quality: an exploratory GBrain component comparison}
\label{sec:context-extension}
To make the memory boundary concrete, we executed the hybrid-search component of GBrain, an open-source general-purpose memory system, on the same verified-event views.\footnote{\url{https://github.com/garrytan/gbrain}, revision \texttt{531b3b1ab66c88f192abb51338028c44b80fbf21}; MIT. The exact adapter and protocol are included in the companion.} This extension was designed after the original study's outcomes were available. It is an exploratory component comparison on reused cases, not a new hidden evaluation or a ranking of complete company-memory products.

The adapter calls the actual upstream PGLite engine, revision-bound page/chunk installation and balanced hybrid-search pipeline. Every method receives the same permitted current facts and the same real recorded Qwen embeddings. The adapter verifies that the semantic arm executes. Provider reranking is explicitly disabled; the fixture has no independently extracted source graph. Native raw-document ingestion, hosted behavior, synthesis and end-to-end authorization or update handling are outside this comparison. Each case initializes an isolated snapshot, so initialization/indexing timings are not steady-state production costs. Requests, native rankings, failures and source snapshots are retained. Saved tokenizer receipts make packet selection and analysis reproducible without a running model.

We compare the returned ranking with \emph{GBrain plus catalog coverage}, which applies the same public prerequisite-selection module to the same saved GBrain pool. This control asks whether the benefit can be composed with general memory rather than requiring a new storage system. No answer labels, acceptable action IDs or future evidence enter either adapter. A larger packet allowance is also important: the original small cap intentionally stresses selection and is not a default setting representative of all company-memory workloads.

The same selection module on GBrain closes the complete-support gap at the smallest allowance. At the intermediate allowance, generic relation diversity also retrieves complete support. At the largest allowance, every compared method supplies complete support. These results bound the architecture claim: prerequisite-aware composition helps on this constrained, typed fixture, but the evidence does not require replacing general memory, choosing a graph or claiming a uniquely marketing algorithm. They also show why reporting only a narrow-budget winner would be misleading. The fictional histories, repeated distractors and already-clean relation labels limit external validity; complete context is not proof of a useful commercial action.

The prospective memory study should compare raw-document extraction and maintenance, native system configurations, a strong direct agent and independently authored company cases. A separate recommendation study should hold the supplied context fixed while comparing direct Claude/GPT with the proposed method within each same backbone. Their shared data and any reused observations must be disclosed. Neither those frontier-provider results nor independent practitioner assessments are supplied by this preliminary report.
