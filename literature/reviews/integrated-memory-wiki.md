## WiCER — arXiv2605.07068v1

Juan M. Huerta, *WiCER: Wiki-memory Compile, Evaluate, Refine: Iterative Knowledge Compilation for LLM Wiki Systems*, preprint8May2026. Read main introduction, related work, setup, methods, results and limitations through§7.5; inspected AppendixJ and checklist inconsistencies. Did not audit all appendices or reproduce code. Owning arXiv metadata and PDF retrieved; paper reports released code, but the consulted text does not establish a pinned accessible licensed repository.

This is directly relevant to the requested Karpathy-style wiki comparator. It distinguishes raw documents, blind compiled knowledge and feedback-refined wikis; preloading a compiled wiki is not equivalent to top-k RAG. On curated30-article/240-question Policygenius data, Table1 reports4.38 versus4.08/5 and median TTFT0.857 versus6.277seconds, using an8B local reader and Claude judge. The full-context prefix is warmed; generation throughput favors RAG. These are different-resource operating points, not evidence that one architecture always costs less. On RepLiQA the direction changes: raw full context scores3.47 versus RAG3.64 (§5), and blind compilation drops to2.14–2.32 (Table3). This is a valuable counterexample to assuming any specialized context is better.

WiCER selects one diagnostic QA probe per document, diagnoses failed probes, and pins facts during recompilation. Table4 evaluates80 probes/topic and reports the best iteration per topic; the main text does not establish a disjoint final evaluation for the refinement gain. Therefore the reported80% recovery is not a demonstrated held-out recommendation benefit. Table5 uses independent stochastic blind compilations for random-versus-diagnosed pinning, so its starting points vary. Strong monotonic-preservation language is not enforced by a formal LLM constraint; AppendixI qualifies the analogy. AppendixJ reports one domain expert's100-item check, including only6/3 items from WiCER iterations1/2; it is not a broad independent human validation of those arms. The checklist says no human subjects, whereas AppendixJ describes a human rating exercise; this inconsistency is recorded rather than silently reconciled. No claim of misconduct follows.

Reuse: include full permitted context, compilation cost/fidelity and a strong file-memory reference; never refine memory with hidden evaluation questions. Our controlled lossless Markdown arm intentionally removes compilation loss as a confound; it cannot be described as reproducing WiCER or benchmarking the complete Karpathy workflow.

## Contract Memory Compiler — arXiv2609.32658v1

Zhi Song and colleagues, *Contract Memory Compiler: Resolve, Then Traverse*, preprint26September2026. Read the main setting, algorithm, experiments, discussion and reproducibility statement; inspected budget/alternative-retriever passages. Did not reproduce supplementary code or audit every appendix. Primary metadata/PDF retained.

This already demonstrates a memory-context intervention with frozen extraction, reader and prompt. CMC extracts typed relations before seeing queries, resolves last-write-wins state, anchors query entities, traverses current relations up to5hops, and returns original sources plus unresolved residuals. Table1 reports78.25% multi-hop versus21.50% when selecting before refreshing, and20.75% fact-BM25. A matched-length BM25 control reaches7.25% versus78.25%; mean inputs182 versus185tokens (§4.1). Dense BGE-M3 improves to33.25% but does not close the gap. Reader swaps in Table2 separate retrieval from answer-model capacity. These are strong design precedents, so "context influences actions" or "resolve before reading" is not our novelty.

Limits relevant to our claims: FactConsolidation labels use substring match; the paper flags potentially superseded answers and reports sensitivity checks. Its raw/latest-state arms truncate600/800queries, hence cannot be treated as unconstrained full-context controls. The task assumes ordered single-valued assertions; it does not model approved policy versus proposals, multiple unresolved values, GTM utility or access control. The authors explicitly acknowledge selection from a broader development grid. The60,000-character cap is distinct from equal realized tokens. Our byte-based study must make the same distinction. Learned raw extraction and exact surface anchors have separate error sources; shared verified events only isolate the read stage.

Reuse: fixed reader/source pools, matched evidence-length controls, separate currency and support, honest truncated/untruncated labels and strong lexical+dense references. The incremental contribution is a reproducible marketing action-eligibility study across current Claude/GPT readers and public memory components, with a generic-coverage falsifier. No new general-memory architecture claim survives this comparison.

## VehicleMemBench — arXiv2603.23840v1

Yuhao Chen and colleagues, preprint25March2026. Read introduction, construction outline, evaluation protocol, model/memory comparison, Table2 and limitations; remaining appendices not comprehensively reviewed.500queries are clustered in50scenarios, not500independent worlds. An executable simulator compares final state to a verified target; textual fields use limited fuzzy matching. Gold-memory experiments isolate tool-use capability, while autonomous memory includes construction/retrieval. Table2's token counts differ markedly across methods; it is not a matched-input proof of general-purpose memory inferiority. Gold support can omit irrelevant complexity and constitutes an intervention, not a complete mediation decomposition. Upstream code/data links are recorded, but no code/data is imported here.

This directly supports separating memory availability from downstream action success without requiring two papers. It also precludes a "first executable domain-memory benchmark" claim. Our contract checks action eligibility and citations; it does not execute a rich vehicle or GTM environment, and mock dry-run success is narrower than a business outcome.

Our lossless structured-file reference is deliberately strong for verified facts: it retains all eligible source records, organizes them by entity/relation/authority, and uses generic field diversity without action-specific priorities. It is original code, not a port of those skills. It receives the same canonical evidence rendering as other arms. This tests whether ordinary files plus coverage suffice; it does not evaluate LLM compilation quality, native filesystem tool use, or the entire wiki lifecycle. Those limits must accompany its name in the paper and figures.

## Updated gap and search stopping decision

The defensible paper integrates two measured outcomes: complete support under bounded reads, and grounded recommendations under the same provider model. A shared-backend GBrain coverage control and domain-neutral Markdown control are essential falsifiers. The source review strengthens the experimental design rather than a universal-superiority story. No new architecture name is needed. Proceed to the pilot; retain unresolved primary-Gist access, comprehensive citation indexing, raw ingestion and practitioner-validation gaps explicitly.
