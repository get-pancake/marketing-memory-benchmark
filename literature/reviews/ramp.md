# RAMP — full-text critical review

Reviewed 22 October 2026 UTC. Source: arXiv:2508.11120v2, *Towards Reliable Multi-Agent Systems for Marketing Applications via Reflection, Memory, and Planning*, Lorenzo Jaime Yu Flores, Junyi Shen and Goodman Gu. The arXiv metadata records first submission 14 August 2025 and revision 18 August 2025. Read the 13-page paper, including methods, experiments, limitations and prompt appendices. Download receipt/hash: `literature/retrievals.jsonl`. Publication status is not inferred from formatting. Results below are the authors' reports, not reproduced results.

RAMP already connects client-specific semantic and episodic memory to marketing plans, executable audience filters, verification and reflection. Its 88 filter queries operate over 15,044 customers with 56 attributes; a separate ten-query challenge set requires changes to an initially unsuccessful plan. Memory is retrieved using BM25. All experiments use GPT-4.1 at temperature zero, three runs. Table 1 separately ablates a planner and semantic memory: actor-only exact audience accuracy is .583, versus .870 with both. This is a 28.7-point difference in a combined intervention, not an isolated benefit of a memory representation. Table 2 reports .853 with the additional verify/reflect loop, versus .870 without it. More machinery does not consistently help.

The challenge tasks and the reflector prompt deserve particular attention. The prompt can drop filters when a threshold or geography is changed (Table 6); the user study always answers “Yes, proceed with audience creation” to clarification. That evaluates a permissive repair interaction, not preservation of an immutable approved targeting policy. It would be inappropriate to import this behavior into Pancake's approved strategy without an explicit proposal/approval boundary. The generated verifier also shares potential specification errors with the generator; passing generated tests is not an independent proof of user intent.

The user study has three product managers judging eight challenge questions, with two additional questions used for practice, using comparative accuracy, transparency and UX criteria. It is genuine reported human assessment, but a small study; the text does not establish independent blinded recruitment or commercial campaign effectiveness. Separately, the ten-query challenge experiment's Table 3 reports accuracy dispersion values greater than one alongside proportions (for example, 0.200 ± 1.83). Visual inspection of the original page 5 confirms these printed values; their scale needs author clarification before uncertainty can be reused. One-sided Mann–Whitney tests on three repeated runs are not a substitute for paired query-level or company-level uncertainty. No matched total-token or ingestion-cost comparison is reported. The memory-count sweep and small challenge set create tuning/selection questions; a held-out company split is not described.

Reuse decision: adopt the separation of planning, hard executable checks and subjective marketing quality as an evaluation lesson. Do not claim novelty for marketing memory plus planning, BM25 memory retrieval, or executable verification. No reusable repository/data license was established from the paper and the initial repository search; this is an access finding, not proof that code is unavailable. Do not reconstruct private customer data.

Remaining distinction worth testing: current, permission-visible evidence for catalog-constrained Play proposals under policy changes, with a shared planner, explicit prompt-only control, full-context reference and separate retrieval coverage/decision correctness. A graph is not needed to pose that question. If a competent generic retriever or full context matches the specialized method, that is a central result.
