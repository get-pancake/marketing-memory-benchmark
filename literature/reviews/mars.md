# MARS — full-text critical review

Reviewed 22 October 2026 UTC. Primary source: arXiv:2605.14401v2, *Agentic Recommender System with Hierarchical Belief-State Memory*. Read all 18 pages, including algorithms, hyperparameters, cost estimates, limitations, case study and prompts. Exact authors/dates are retained from canonical metadata in the verified bibliography. Results are source-reported, not reproduced.

MARS already separates raw events, mutable preference chunks and a synthesized profile, with extraction, reinforcement, weakening, consolidation, forgetting and resynthesis. An LLM schedules maintenance; a separate ranker consumes recent events and a profile. Thus neither a three-layer memory nor a generic “memory-to-recommendation” story can be claimed as new here. The POMDP is a conceptual framing, not a learned optimal control policy or calibrated Bayesian filter: §3.3 explicitly uses deterministic heuristic updates. Calling strength/evidence fields “confidence intervals” (§3.2) does not supply a sampling model or calibration test. We should not reuse that statistical terminology for uncalibrated scores.

The retrospective evaluation covers four InstructRec domains, using the latest interaction as a positive and nine randomly sampled negative candidates. All LLM methods use Llama-4-Maverick-17B-128E-Instruct by default; traditional BPR, LightGCN and SASRec are retained. Table 2 reports gains in HR/NDCG, and notes strong conventional baselines on denser data. These metrics evaluate sampled item ranking, not whether a proposed business workflow respects approved policy or produces revenue. Negative sampling and instruction availability limit transfer to unrestricted recommendation.

The evolving comparison uses two 100-user Books samples; agentic scheduling improves some outcomes, but fixed MARS is below i2Agent on Light User HR@1 (.510 vs .600, Table 3), despite prose describing it as matching that baseline. The profile/event ablation changes what the ranker sees; preference memory still contributes through profile synthesis. It therefore does not establish that removing the preference-maintenance tier has no cost. Appendix F supplies one selected successful trajectory, not a distributional test of revision quality.

The retrospective token analysis reports 3,870 tokens/user for MARS versus 8,849 for MemRec. Appendix D converts estimates using Gemini 2.5 Flash prices while the actual backbone is Maverick; those USD values are reference-price calculations, not paid receipts. Evolving costs are much greater. Appendix E explicitly reports no error bars and cites greedy decoding as a reason: this controls sampling randomness, not uncertainty over users or heterogeneous histories. A parameter-capacity sweep is not a sampling-variance estimate. We will retain world-level uncertainty even at temperature zero.

Reuse decision: preserve the conceptual separation between observations and inferred state and report maintenance costs, but do not transplant preference-strength heuristics into approved GTM policy. Code/data licenses and exact evaluation artifacts remain to be verified before reuse. Relevant backward chain: InstructRec/iAgent, MemRec, AgentCF, CoALA, MemGPT and classical POMDP/case-based recommendation. Our contribution must concern bounded evidence support and selective response to changes, not rediscovering recommendation memory.
