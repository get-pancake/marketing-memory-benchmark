# Development and tuning disclosure

## Current Opus challenge (v4)

Design and schema were fixed before development reader execution; the first pilot used 12 worlds, 36 cases, six contexts and two readers: 432 completed calls. Six unsafe outputs on two negative cases treated a later timestamp as supersession despite unresolved current conflicts. The same current-view clarification was added to every treatment. Labels, scorer and original pilot results were retained. A targeted 72-call validation reused six development cases, including all conflict-error cases and positive controls; all were technically complete with zero unsafe outputs. It is not an independent test sample. Exact pre-amendment source snapshots accompany the first pilot.

The predeclared precision rule uses the first pilot’s maximum company-level paired SD of 0.2124443755. Its rounded calculation gives 72 worlds; the declared minimum selects 120 new main worlds, 360 cases and 4,320 attempts. The final methods/data revision is `54ac3c01c7df5a45d90a9bdfa15c873b99221716`; the freeze hashes 17 producer/scorer/analysis dependencies and all input packets before main generation. One response per condition, no automatic retry/repair, no early stopping, no selection of main cases and no outcome-driven enlargement.

A generic query-word selector was added before the main freeze after finding that it matched all 36 pilot GTM packets. All 360 main inputs were checked before aliasing any main result. The control receives no specialized relation allowlist or labels; it uses relation words already present in the shared query. Its identical-input result bounds the architecture claim and adds no independent observations.

An embedding receipt-path error saved 67 real responses but initially failed cache processing. Recovery rebuilt the cache from those exact responses, without reissuing them; failures and recovery remain under `pilot-context-v1`. The subsequent preparation reused those vectors. No failed preparation was relabeled as fresh inference.

The wider-budget analysis (4–128 KiB) is a predeclared descriptive retrieval sweep, not a new reader experiment. The 132-call external Opus replay was separately specified before its calls, reusing the exact earlier raw/wiki contexts and visible development labels. Earlier GPT/Sonnet efforts and limits differ; their results are historical, not a model-only comparison. The new abstract and figures are written after final analysis; no inferential method is tuned on them.

## Integrated provider study (v3)

The architecture, generator and relation families inherit historical development; only company worlds and requests are fresh. The latest seven-arm comparison uses the same strong domain-aware prompt for every context, with real shared OpenAI vectors. The separate four-world development pilot used hiring/migration families; the main33 worlds use renewal/partner/compliance. Those three families were already known in historical development, so they are not wholly unseen tasks.

The first provider pilot issued132 requests before stopping on eight malformed Claude JSON outputs. Its124 valid outputs and316 unissued plans are retained. Common native JSON-schema support was then applied to both readers. Integration schema errors are preserved. A separate complete448-request pilot had no serialization failures and produced paired world SD0.21650635. The prespecified precision rule selected33 worlds. All main code, model configuration, data and analysis were frozen at61c57c6 before any main reader request. No main outcome selects a prompt, reader, seed, sample size or context allowance. There is no main response cache/reuse:3696 planned requests are distinct actual calls.

The external wiki development track is separate from the main freeze. Synchronous compilation hit client/service time limits; native background responses changed transport only. A common14k output allowance proved insufficient for complete wikis, so the final v4 pair uses32k maximum tokens for both compiler arms with the original10k-target prompts. These changes precede external QA and never supply question/answer feedback to the compiler. All failed and truncated generations remain. The final pair is selected by the documented common configuration, not by choosing the best QA score among compilations. No compilation is refined against the22 development answers.
